과제 07: 인접 행렬과 인접 리스트의 성능 비교

 1. 실행 방법

```
gcc -Wall -O2 -o graph_compare graph_compare.c
./graph_compare 1791805805
```

- 뒤에 숫자(seed)를 쓰면 매번 같은 결과가 나온다. 이 README는 seed 1791805805로 실행한 결과이다.
- 숫자를 안 쓰면 현재 시간이 seed가 되어서 실행할 때마다 결과가 달라진다.
- 내 MacBook에서 실행했다. 64비트라서 int는 4바이트, 포인터는 8바이트, Node는 16바이트이다.

2. 프로그램 설명

- 정점 100개인 무방향 그래프를 만들었다. 자기 자신과 연결하는 간선과 같은 간선을 두 번 만드는 것은 하지 않았다.
- 간선을 랜덤으로 먼저 만들고, 같은 간선으로 인접 행렬과 인접 리스트를 만들었다.
- 인접 행렬은 `int matrix[100][100]`이다. 간선 (u, v)가 있으면 `matrix[u][v]`와 `matrix[v][u]`를 둘 다 1로 했다.
- 인접 리스트는 정점마다 연결 리스트를 만들었다. 간선 (u, v)가 있으면 u의 리스트에 v를, v의 리스트에 u를 넣었다.
- 삽입, 삭제, 연결 확인, 인접 정점 출력은 두 방법에서 같은 정점으로 했다.
- 메모리는 `sizeof`로 계산했다.
  - 인접 행렬 = 구조체 크기
  - 인접 리스트 = 구조체 크기 + (노드 개수 × `sizeof(Node)`)
  - 랜덤 간선을 만들 때 쓴 임시 배열은 메모리에서 뺐다.

 비교 횟수를 세는 방법

| 연산 | 인접 행렬 | 인접 리스트 |
|------|-----------|-------------|
| 간선 삽입 | `matrix[u][v]`를 1번 확인 | u의 리스트에서 같은 간선이 있는지 확인한 노드 수. 삽입은 리스트 맨 앞에 해서 비교가 없다 |
| 간선 삭제 | `matrix[u][v]`를 1번 확인 | u의 리스트에서 v를 찾고, v의 리스트에서 u를 찾은 노드 수의 합 |
| 연결 확인 | `matrix[u][v]`를 1번 확인 | u의 리스트에서 v를 찾을 때까지 확인한 노드 수 |
| 인접 정점 출력 | `matrix[u][0]`부터 `matrix[u][99]`까지 100번 확인 | u의 리스트에 있는 노드 수 |

 4. 분석

4-1. 메모리

인접 행렬은 간선이 100개여도 4000개여도 메모리가 40,008바이트로 같았다. 행렬의 크기는 정점 수(100 × 100)로만 정해지기 때문이다.

인접 리스트는 간선이 많아지면 메모리도 많아졌다. 무방향 그래프라서 간선 1개에 노드가 2개 필요하다.

- Sparse: 노드 200개 × 16바이트 + 808바이트 = 4,008바이트
- Dense: 노드 8000개 × 16바이트 + 808바이트 = 128,808바이트

Sparse에서는 리스트가 행렬보다 약 10배 적게 썼다. 그런데 Dense에서는 리스트가 행렬보다 약 3.2배 더 많이 썼다. 리스트의 노드는 정점 번호(4바이트)뿐만 아니라 다음 노드를 가리키는 포인터(8바이트)도 있어서 16바이트나 되기 때문이다.

### 4-2. 희소 그래프 (정점 100개, 간선 100개)

- 한 정점에 연결된 간선이 평균 2개 정도라서 리스트가 아주 짧다.
- 삽입, 삭제, 연결 확인은 행렬이 항상 1번이라서 가장 빠르다. 리스트도 평균 2~4번이라서 차이가 크지 않았다.
- 인접 정점 출력은 리스트가 훨씬 좋았다. 행렬은 인접 정점이 3개뿐인데도 100칸을 전부 확인했다. 리스트는 3번만 확인했다. 평균도 약 2번이었다.
- 메모리도 리스트가 훨씬 적게 썼다.
- 그래서 희소 그래프에서는 인접 리스트가 더 좋다고 생각한다.

4-3. 밀집 그래프 (정점 100개, 간선 4000개)

- 한 정점에 연결된 간선이 평균 80개 정도라서 리스트가 길다.
- 행렬은 삽입, 삭제, 연결 확인이 모두 1번이다. 리스트는 평균 48~79번이라서 많이 느려졌다.
- 한 번 뽑은 값에서는 삭제가 149번으로 가장 많았다. 삭제는 두 정점의 리스트를 모두 찾아야 하기 때문이다. 그런데 평균으로 보면 삽입(79.12)과 삭제(78.14)가 비슷했다. 삽입은 한 리스트를 끝까지 확인하고, 삭제는 두 리스트를 중간쯤까지 확인하기 때문이라고 생각한다.
- 인접 정점 출력은 행렬이 100번, 리스트가 평균 약 80번이었다. 리스트가 조금 적지만 차이가 크지 않았다.
- 메모리는 행렬(40,008)이 리스트(128,808)보다 훨씬 적었다.
- 그래서 밀집 그래프에서는 인접 행렬이 더 좋다고 생각한다.

 4-4. 언제 어떤 방법을 쓰면 좋을까?

| 상황 | 추천 | 이유 |
|------|------|------|
| 간선이 적은 그래프 | 인접 리스트 | 메모리가 적고, 인접 정점을 빨리 찾는다 |
| 간선이 많은 그래프 | 인접 행렬 | 메모리가 더 적고, 삽입·삭제·연결 확인이 1번이다 |
| 두 정점이 연결됐는지 자주 확인할 때 | 인접 행렬 | 항상 1번만 확인한다 |
| 한 정점의 인접 정점을 자주 볼 때 (BFS, DFS 등) | 인접 리스트 | 연결된 정점만 확인한다 |
| 정점이 아주 많을 때 | 인접 리스트 | 행렬은 정점 수의 제곱만큼 메모리가 필요하다 |
 5. 느낀 점

이 실험으로 그래프의 밀도에 따라 좋은 방법이 달라지는 것을 알게 되었다. 인접 행렬은 간선이 몇 개든 메모리와 비교 횟수가 거의 같았다. 인접 리스트는 간선이 많아지면 메모리와 비교 횟수도 같이 늘어났다. 그래서 항상 더 좋은 방법은 없고, 그래프가 희소한지 밀집한지와 어떤 연산을 자주 하는지 보고 골라야 한다고 생각했다.
